# Read-only layer-switch diagnosis

The production promotion of exact Atmos `5b622f594b107e105dae9ee6b494c20ff8d0699a` rolled back after the layer-switch guard failed during cache prefill. The existing generic timeout did not identify which requested field or whether it was still loading or had failed. This manual Ubuntu lane gathers that missing evidence without another production deployment.

Only `main` workflow dispatch through this exact workflow/job is admitted. Choose `staging` or `failed-preview`; these resolve to `https://staging.weatherx.org` and the immutable failed candidate `https://73c343d0.atmos-platform-dnp.pages.dev`. There is no arbitrary origin or source input. Receipt/source/release/index checks require the reviewed candidate. The fixed controller checkout uses only the existing Atmos source key with persisted credentials disabled; the browser process receives no inherited credentials. The job uses the existing protected `staging` environment because its source checkout needs the Atmos deploy key. It has contents-read permission only and no publication, account mutation, data write, or release-fuse operation; environment protection does not grant those capabilities.

The helper verifies the exact original layer-switch harness and its surface helper SHA256 before creating an instrumented local copy. It verifies the same receipt bytes and actual HTML again after the guard returns or fails. Original waits, thresholds, hostile switch sequence and assertions remain unchanged, including the 30-second prefill wait. It adds observations before/after each prefill wait and on failure. HTTP failures, bounded request-path categories, GPU error codes, selected layers, swap state, a compact deck snapshot and timings are retained. The browser rejects non-GET/HEAD/OPTIONS requests before navigation. Playwright routing disables its HTTP cache; that instrumentation difference is recorded in the identity receipt and must be considered when interpreting timing. No bodies, headers, query strings, raw console messages, source code, screenshots or browser profiles are uploaded. Original guard output is not retained; controlled JSONL observations are limited to 1 MiB, plus small identity/result receipts. A 15-minute process-group deadline bounds a stuck diagnostic; job timeout is 20 minutes. The artifact is retained 7 days, including failures.

Use staging for the first Ubuntu run. The immutable preview serves the exact HTML and data index, but its `/api/platform/health` route returns 404 while staging returns 200; a local preview attempt timed out before prefill, so preview startup failure cannot explain the production prefill failure.

This lane cannot qualify or promote an artifact. A successful reproduction does not establish that the original failure was flaky. Review failure state and network/GPU evidence, and keep the production fuse unchanged until the failure is explained and the separate release gates are satisfied.

Validation: `node --test tests/ui-layer-diagnostics.mjs`; `node tools/workflow-inventory.mjs --check`. Existing scheduler CI runs the new test through its `tests/ui-*.mjs` selection. No existing UI policy file or pipeline digest is changed by this diagnostic-only lane.

The diagnostic snapshot includes the last 40 in-flight requests (from a map capped at 256), their elapsed times, and allowlisted numeric decode-worker and texture-budget counters. A renderer snapshot has a separate two-second deadline so a wedged renderer still produces a timeout record. Finished and failed requests leave the in-flight map.
