The production promotion of exact Atmos `5b622f594b107e105dae9ee6b494c20ff8d0699a` rolled back after the layer-switch guard failed during cache prefill. Those historical diagnostic bindings remain fixed. The later staging run `37413651923`, for exact Atmos `547a8e1e54a7e46b211ea0770d895b6cc46c8afd`, also failed the strict layer guard and rolled back. Its original child error was not retained; the outer assertion does not establish a cause. This manual Ubuntu lane gathers bounded evidence from the fixed failed preview before another staging attempt.

Only `main` workflow dispatch through this exact workflow/job is admitted. Choose `staging`, `failed-preview`, or `recovery-preview`. The first two retain the historical source/release/index bindings and resolve to `https://staging.weatherx.org` and `https://73c343d0.atmos-platform-dnp.pages.dev`. `recovery-preview` resolves only to `https://2fd3d799.weatherx-platform-staging.pages.dev` and binds source `547a8e1e54a7e46b211ea0770d895b6cc46c8afd`, release `git-547a8e1e54a7-run-37413651923`, and HTML SHA256 `1183bb846808b0d628333c17cbbb6e1edfead1b74afbdc194710fd1c321ad697`. Its original harness SHA256 is `d686f763ce892d2b6288c8caafa0924bf0bef6328847ad3806bd0f395b8e632b`; its surface helper SHA256 remains `3e6244dc1df4529174cf8e5a65668706f542931d685169d54b88c71c34f8fbe4`. There is no arbitrary origin, source, release or index input. The conditional controller checkout selects between these two fixed sources. Receipt/source/release/index checks require the selected reviewed candidate. The fixed controller checkout uses only the existing Atmos source key with persisted credentials disabled; the browser process receives no inherited credentials. The job uses the existing protected `staging` environment because its source checkout needs the Atmos deploy key. `deployment: false` retains that protection without creating a GitHub deployment-history record. Earlier diagnostic runs could create that metadata record; they did not publish the site. It has contents-read permission only and no publication, account mutation, data write, or release-fuse operation; environment protection does not grant those capabilities.

The helper verifies the exact original layer-switch harness and its surface helper SHA256 before creating an instrumented local copy. It verifies the same receipt bytes and actual HTML again after the guard returns or fails. Original waits, thresholds, hostile switch sequence and assertions remain unchanged, including the 30-second prefill wait. It adds observations before/after each prefill wait and on failure. Unique exact stage anchors label startup, baseline preparation/capture, prefill and later guard sections; a missing or duplicated anchor refuses instrumentation. Fatal rows retain an allowlisted `stage`, an `originalSourceLine` checkpoint number, and a `failureCode` from exact known fixed throws in the reviewed surface helper, harness and strict-baseline observer. The line identifies the last original harness checkpoint, not the exact throwing line. Known Playwright `page.evaluate: Error: ` wrappers are recognized from their first line; dynamic or unknown messages yield a null code. Neither error messages nor stacks are emitted. HTTP failures, bounded request-path categories, GPU error codes, selected layers, swap state, a compact deck snapshot and timings are retained. The browser rejects non-GET/HEAD/OPTIONS requests before navigation. Playwright routing disables its HTTP cache; that instrumentation difference is recorded in the identity receipt and must be considered when interpreting timing. No bodies, headers, query strings, raw console messages, source code, screenshots or browser profiles are uploaded. Original guard output is not retained; controlled JSONL observations are limited to 1 MiB, plus small identity/result receipts. A 15-minute process-group deadline bounds a stuck diagnostic; job timeout is 20 minutes. The artifact is retained 7 days, including failures.

Use `recovery-preview` with `strict-paint` to diagnose staging run `37413651923` on the Ubuntu lane. Canonical staging rolled back to another release, so `staging` remains an identity mismatch and refuses before browser navigation. Local macOS runs of the recovery preview passed the five strict paint observations and the original roundtrip, including a software-GL/CPU-throttled trace; this does not identify the Linux/canonical failure because the runner and backend differ. The earlier historical preview has separate startup/backend limitations and is not interchangeable with the recovery target.

This lane cannot qualify or promote an artifact. A successful reproduction does not establish that the original failure was flaky. Review failure state and network/GPU evidence, and keep the production fuse unchanged until the failure is explained and the separate release gates are satisfied.

Validation: `node --test tests/ui-layer-diagnostics.mjs`; `node tools/workflow-inventory.mjs --check`. Existing scheduler CI runs the new test through its `tests/ui-*.mjs` selection. Changes to the controller's policy-bound diagnostic tools require the normal pipeline digest metadata and review checks.

The diagnostic snapshot includes the last 40 in-flight requests (from a map capped at 256), their elapsed times, and allowlisted numeric decode-worker and texture-budget counters. A renderer snapshot has a separate two-second deadline so a wedged renderer still produces a timeout record. Finished and failed requests leave the in-flight map.


The optional `mode` input defaults to `original`. `strict-paint` adds a separate 30-second paint proof after each unchanged original prefill wait, before the next activation. It first requires a current ledger baseline and a different selected primary, then verifies exactly one new semantic intent with the same model, run, base and cursor. The pinned controller advances that clock once for each atomic primary-family change; a stale baseline fails as unavailable rather than guessing a generation.

Strict mode reuses the pinned controller's Temperature and Wind surface predicates. A legitimate native Temperature or Wind owner can pass without a Deck texture pair. Scalar Deck owners require a new accepted draw/flush/receipt chain and loaded bound textures. Evidence records `owner` and `authoritativeDeck` separately: proven native paint does not establish full Deck cache population. On failure, bounded causal events, swap/preview state, loaded texture flags and request/decode counters remain available. The added wait changes the prefill pacing deliberately; this mode is diagnostic evidence, not release qualification, a fix, or proof that the historical timeout was reproduced. All original later assertions still run.

Strict paint observation polls every 250 ms, rather than every animation frame, to bound diagnostic ledger copying and native-owner snapshot overhead. This adds up to one polling interval to detection time and is another reason to treat strict-mode timings as diagnostic only. The original guard polling and timeouts are unchanged.
