# Public output security boundary

This change is packaging and CI diagnostics only. It does not deploy an application,
change data publication, move credentials, alter schedules, or add browser code.

## Bake diagnostics

The final `cycle log` step projects a bounded set of typed progress fields from
the newest regular bake log. Arbitrary checkpoint text, stack traces, paths, and
the previous raw last-200-lines output are not printed. Unknown records are
omitted; they must not be restored through a plaintext fallback.

The original `bash ops/bake-weatherx.sh` publisher and its live progress channel
remain unchanged. Detailed diagnostics retain only the last 16 KiB, encrypted
with the existing diagnostic owner public key. The receipt is non-publishable,
contains no plaintext tail, and expires from Actions artifacts after three days.
Retention and upload are best effort, independent of publication success.
The owner must use the matching existing private key to read the tail; that key
is neither added to Actions nor generated by this change.

The projector caps lines at 4 KiB, output at 10,000 records, and accepted input
logs at 1 GiB. Parsing is streamed, rather than loading a whole bake log into
memory. A projection/encryption failure produces a fixed public message, not raw
diagnostics. Failure/cancellation of the publisher is not hidden or rewritten.

## UI candidates

The candidate guard rejects known private source/config paths, source maps,
inline source-map references, and named high-confidence credential signatures.
Checks apply before encryption and again when a candidate is decoded.
Compiled Worker assets and verified JS/CSS compression sidecars remain allowed.
These checks prevent specified accidental inclusions; they are not a universal
secret detector and cannot make JavaScript delivered to a browser confidential.
Hidden paths are denied, including `.well-known`; if a future native association
file is needed, admit its exact reviewed public route with a compatibility test
rather than exempting every hidden file.

`tools/ui-candidate.mjs` is bound into the release policy digest. After this change
merges, a future promotion requires fresh staging qualification under the new
policy. Do not bypass that check or try to reuse an older qualified candidate.
Existing deployed sites are unaffected by committing or reviewing this branch.

## Verification and scope

Regression tests use synthetic private markers, malformed records, oversized
lines, encrypted-tail round trips, private paths, and authenticated malformed
candidates. Existing scheduler, publication, UI transfer, compression and Worker
contracts must remain green. Run the checks registered in scheduler CI before
merge. Repository secret scoping and historical artifact retention are separate
work: this change neither revokes a source key nor removes past public logs.
